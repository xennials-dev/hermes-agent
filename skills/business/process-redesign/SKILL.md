# Process Redesign (The AOA Framework)

## Trigger Conditions
Use this skill when:
- A client's workflow is broken, bloated, or has too many human handoffs
- Automation attempts have failed due to underlying procedural chaos
- Mapping As-Is vs. To-Be operational blueprints

---

## 1. The Core Philosophy
> *"Automating an inefficient process only creates automated inefficiency."*  
> Always **Audit** and **Optimize** before writing a single line of automation code.

---

## 2. The 3-Step AOA Framework

### Step 1: Audit (Current State Map)
- Trace the current workflow step-by-step from trigger to completion.
- List all tools, spreadsheets, emails, and staff touchpoints involved.
- Count the total number of steps and identify handoff bottlenecks.
- *Example*: A 16-step quoting and invoicing flow with 4 manual copy-paste steps.

### Step 2: Optimize (Future State Blueprint)
- Delete non-value-add steps.
- Consolidate redundant data entry points into a single source of truth.
- Standardize required inputs and validation rules.
- Reduce step count by 40%–60% (e.g. 16 steps down to 6 clean steps).

### Step 3: Automate (Hermes & Integration Layer)
- Automate the streamlined To-Be process using Hermes Agent, webhooks, or n8n/Make.
- Set up automated error alerts and failure fallbacks.
